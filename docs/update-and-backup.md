# 更新、签名与备份

## 两种备份

学习记录由App导出JSON，包含课程标识、实际成绩、收藏、意见和草稿。它用于恢复学习状态，不包含打包签名。卸载、清除数据或换设备前先导出，并核对文件可以读取。

制作工程备份包含课程JSON、配置、实际用到的图片、来源映射和私有原资料。`.signing/`及其密码需在安全位置单独或连同私有工程备份；二者均不能进入公开仓库或公共源码附件。

## 同一软件更新

1. 核对当前工程、`applicationId`、课程ID、签名和上次版本；确认这确实是同一软件。
2. 保留知识点ID与显示编号。题义完全改变时使用新题ID，旧题加入`legacy.questions`以识别历史成绩。
3. 合并知识点通过`legacy.lessonAliases`映射，保留每条收藏和核对文字并去重，重复启动不反复追加。
4. 修改真正的课程来源入口，生成运行数据；检查关联题目和同类显示问题。
5. 递增`versionCode`，按需要更新`versionName`与课程版本，验证后用原签名构建。
6. 按用户授权覆盖安装，保留记录；实机只做必要导航，不提交测试答案。

本地构建器记录签名摘要与安装身份；内容变更却未递增版本、切换签名或身份时停止，提示恢复原配置或建立独立项目。已有签名丢失时不悄悄生成替代密钥。

## 本地签名

首次构建生成每个项目独立的随机密码和签名，保存在该项目的`.signing/`，证书名称使用通用值。文件不会装入APK。此方式适合本地侧载试用；公开发行前根据分发方式管理正式签名。

使用已有密钥时提供`--keystore`和`--alias`，通过`STUDYAPP_KEYSTORE_PASSWORD`环境变量传密码；命令与报告不写出密码。外部证书可能包含持有人的信息，发行前检查证书内容。

## 框架升级与课程升级

课程项目记录其套件版本。升级框架时先备份，用差异对照迁移运行代码；保留`course-data.json`、`app-config.json`、`production.json`、课程资源、`.local/`和`.signing/`。先在副本验证旧备份、草稿、历史题和意见，再更新正在使用的工程。

当前不提供自动框架合并工具。不要用重新创建项目覆盖旧目录；创建器会拒绝已有目录。
