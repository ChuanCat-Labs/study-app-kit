# 检查与交付

## 分开记录三类检查

| 类型 | 依据与可说明的结果 |
| --- | --- |
| 内容核对 | 原资料、用户纠正、来源映射与逐点清单；条目、条件、重点、范围和关联题是否正确 |
| 实际显示 | 目标尺寸的页面、公式几何、图片、编号与荧光边界；不能只检查字符串存在 |
| 功能与记录 | 真实交互、作答统计、草稿恢复、导出导入、旧ID迁移；使用隔离测试数据 |

完整内容检查覆盖所有现用知识点和题目；局部修订检查受影响组及同类问题。保留具体未确认项，别把空清单或“全绿”界面当作事实正确。

数学显示检查同时覆盖单个分式、下标及完整混合算式。若完整公式被竖着排开，检查CSS是否将原生MathML容器改成了普通块布局；当前框架保留`display: block math`。观察算符可见性、各项的实际水平位置和目标尺寸截图，不能只断言`mfrac`、`msub`标签存在。

## 套件测试

```sh
npm test
node tools/serve.mjs --port 8000
```

另开终端运行浏览器检查，首次准备测试环境时需要：

```sh
npm install
npx playwright install chromium
npm run test:browser
```

有现成Playwright时可通过`PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`、`BASE_URL`使用指定环境。浏览器检查使用独立上下文和中性示例，不接触真实手机或用户的预览记录。

新增工具测试覆盖创建不覆盖、默认课程隔离、来源原样保存及去重、项目自包含、运行资源允许清单、私有文件不被预览服务暴露、发布清单遗漏与隐私扫描。自动扫描结果只说明检测范围，仍需人工审阅实际图片与内容。

## APK检查

构建器校验签名、对齐、安装身份、所有运行资源和原图标的一致性；报告在工程`output/build-report.json`。构建不等于实机安装验证。安装后另记实际打开范围和版本，不替用户答题或改进度。

## 对用户交付

交付完整APK、必要源码和简短变更说明，说明内容核对、浏览器与实机验证各自范围。制作工程与学习记录的备份分别说明；密钥和凭据不放公共附件。尚待确认的知识项按具体位置列出。

## 发布通用套件

```sh
node tools/audit-public.mjs --report output/public-audit.json
```

`public-files.json`是明确的通用文件清单，默认课程必须为空；真实资料、构建产物、学习记录和密钥不在其中。可用`--deny-file`提供仓库外的私人词表，报告只写规则与文件，不回显匹配原文。

上传前还要核对干净的Git提交身份、许可和默认图标的分发选择。构建日志、截图、压缩包和发布附件也按实际清单复查，不能认为`.gitignore`会处理已提交的文件。
